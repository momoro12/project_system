## Блок 1: Персонал аэропорта и кадровая структура

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-ПЕР-01 | Система должна вести единый реестр работников аэропорта с персональными и кадровыми данными | ФИО, дата рождения, пол, контакты, стаж работы, должность, отдел, заработная плата, количество детей |
| ФТ-ПЕР-02 | Система должна относить каждого работника ровно к одному отделу | Пилоты, диспетчеры, техники, кассиры, служба безопасности, справочная служба и другие подразделения |
| ФТ-ПЕР-03 | Система должна поддерживать уникальные профессиональные атрибуты работников в зависимости от категории | Для пилота → класс, налёт, допуски; для диспетчера → зона ответственности; для техника → специализация; для кассира → кассовый пункт |
| ФТ-ПЕР-04 | Система должна хранить информацию о начальниках отделов как представителях администрации аэропорта | Начальник отдела, дата назначения, зона ответственности, полномочия |
| ФТ-ПЕР-05 | Система должна позволять формировать выборки работников по отделу, стажу, полу, возрасту, наличию детей и размеру заработной платы | «Все работники службы безопасности старше 40 лет с зарплатой выше заданного значения» |

| ФТ-БРГ-05 | Система должна позволять получать списки работников бригады по всем отделам, по указанному отделу, по возрасту и по средней/суммарной зарплате | «Бригады техников, обслуживающие рейс SU-145, со средней зарплатой выше заданного значения» |

## Блок 4: Рейсы и расписание

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|

| ФТ-РЕЙ-02 | Система должна поддерживать категории рейсов | Внутренние, международные, чартерные, грузоперевозки, специальные |

| ФТ-РЕЙ-04 | Система должна учитывать, что для специальных рейсов расписание не формируется | Спецрейсы оформляются как отдельные события по факту назначения |
| ФТ-РЕЙ-05 | Система должна учитывать, что на грузовые и специальные рейсы билеты не продаются | Для таких категорий недоступны операции бронирования и продажи пассажирских билетов |
| ФТ-РЕЙ-06 | Система должна позволять планировать рейсы администрацией аэропорта с учётом кадрового состава и доступности самолётов | Проверка занятости самолётов и обслуживающих бригад |
| ФТ-РЕЙ-07 | Система должна фиксировать изменение статуса рейса | Запланирован, задержан, отменён, выполнен |
| ФТ-РЕЙ-08 | Система должна хранить причины задержки или отмены рейса | Погодные условия, технические неполадки, недостаточная продажа билетов и иные причины |
| ФТ-РЕЙ-09 | Система должна позволять формировать выборки рейсов по маршруту, длительности, цене билета, времени вылета и типу самолёта | В том числе по нескольким критериям одновременно |

## Блок 10: Безопасность и администрирование

| ID | Функциональное требование | Уточнения |
|----|---------------------------|-----------|
| ФТ-БЕЗ-01 | Система должна требовать обязательную авторизацию пользователей с разграничением прав доступа по ролям | Администратор, начальник отдела, диспетчер, кассир, техник, сотрудник службы безопасности, справочная служба |
| ФТ-БЕЗ-02 | Система должна вести журнал аудита изменений критически важных данных | Изменения по рейсам, билетам, составу бригад, меддопускам, техосмотрам |
| ФТ-БЕЗ-03 | Система должна обеспечивать защиту персональных данных работников и пассажиров | Разграничение доступа, маскирование чувствительных данных, шифрование |
| ФТ-БЕЗ-04 | Система должна поддерживать настройку справочников без изменения кода | Категории рейсов, типы самолётов, причины задержек и отмен, должности, типы работ |
| ФТ-БЕЗ-05 | Система должна предоставлять API для интеграции с внешними системами | Погодные сервисы, таможенные системы, сервисы продажи билетов, бухгалтерские и кадровые системы |
